# investment-research 开发路线图

## 1. 目标与边界

本项目是个人投研、回测与提醒工作台，面向以美股和 A 股为主、港股为观察市场的日频/低频研究。目标是形成可追溯的研究证据、可复现的回测和经人工确认的提醒流程。

不做以下事情：

- 不修改或合并上游 OpenBB、Qlib、vn.py、daily_stock_analysis、ai-hedge-fund。
- 不把免费或延迟行情用于自动交易。
- 不让 LLM 结论直接成为买卖或下单指令。
- 未完成模拟盘、风控与人工审批前，不保存或使用真实交易凭据。

## 2. 外部项目职责

| 项目 | 在本项目中的职责 | 不承担的职责 |
|---|---|---|
| `daily_stock_analysis` | 多市场盘后复盘、中文报告、低频提醒和通知 | 可验证回测、实时交易 |
| OpenBB | 美股/ETF、SEC、宏观数据的结构化查询与研究 | 自营行情、下单、统一实时流 |
| Qlib | 固定口径历史数据上的日频/低频研究、回测和样本外验证 | 盘中实时交易 |
| vn.py | 最后阶段的模拟盘、行情事件、订单状态与风控 | 未经验证策略的实盘自动化 |
| ai-hedge-fund | LLM/多 Agent 研究工作流的设计参考 | A 股/港股主系统、实盘执行 |

所有上游仓库保持独立环境。本项目通过适配器、导出文件或本地 API 使用其能力，不复制其内部业务逻辑。

## 3. 当前状态

已具备：

- `config/watchlists.json`：美股、A 股、港股观察列表。
- `daily-review` 命令：生成带 UTC 时间戳的研究任务清单。
- `docs/data-contract.md`：数据最小元数据约定。
- 未启用的 macOS `launchd` 每日任务模板。

当前未具备：外部行情、基本面、新闻、LLM、通知、实时提醒、回测、模拟盘、券商或下单能力。

## 4. 数据原则（所有阶段强制执行）

每份进入研究、提醒或回测的数据都记录：`symbol`、市场、`provider`、`fetched_at`（UTC）、`timestamp`、`timezone`、`interval`、`adjustment_method`、`currency`。

- 原始数据放在 `data/raw/`，清洗后数据放在 `data/processed/`，默认不提交 Git。
- 回测只读取版本固定、口径统一的数据集；不得将不同复权、时区或可得时间未知的数据混用。
- 财报和新闻必须记录实际可得时间，避免前视偏差。
- 所有报告显示数据来源与更新时间；数据缺失时明确降级，不伪造结果。

## 5. 分阶段实施

### 阶段 1：盘后研究最小闭环

目标：每天手动或定时生成观察列表的盘后研究记录。

实施项：

1. 扩展观察列表，增加名称、资产类别、基准、优先级和备注。
2. 新增 `src/investment_research/data/` 适配器接口与本地缓存布局。
3. 先接一个可信的日频价格来源；美股/ETF/宏观/SEC 优先尝试 OpenBB，A 股使用单一已验证来源。
4. 生成统一 Markdown 报告：市场概览、价格/成交量、财报/新闻待办、宏观日历、数据质量告警。
5. 手动运行两周，核对时区、交易日、代码映射和复权口径。

验收：可对每个观察标的追溯数据来源和时间；无数据时报告明确标记；不含买卖指令。

### 阶段 2：ETF、财报与宏观研究

目标：把“价格变化”扩展为基本面与宏观上下文。

实施项：

1. 美股个股：通过 OpenBB 获取财报、SEC 文件、估值和分析师预期，保存摘要与来源链接。
2. ETF：记录费用率、前十大持仓、行业/国家权重、重叠度及基准。
3. 宏观：跟踪 CPI、PCE、就业、利率与 FOMC；记录发布日期、预期值与实际值。
4. 建立研究模板：事实、变化、风险、待验证假设与数据来源分栏。
5. 仅在结构化事实齐全时调用 LLM 做摘要；LLM 输出需标为“观点/假设”。

验收：任一报告可区分事实、来源、AI 摘要与未确认信息。

### 阶段 3：筛选与低频提醒

目标：形成可解释的候选池和人工复核提醒。

实施项：

1. 将筛选规则配置化，例如流动性、趋势、波动、估值、财报日期和 ETF 暴露。
2. 接入 `daily_stock_analysis` 的盘后报告能力，保持本项目自己的数据口径记录。
3. 实现日频提醒：收盘涨跌幅、均线状态、成交量异常、财报/宏观事件。
4. 先接一个通知渠道，通知中必须包含触发条件、数据时间、来源和“需人工核验”标记。
5. 记录触发日志、去重规则和冷却时间。

验收：提醒可以复现；不会触发下单；同一信号不会重复轰炸。

### 阶段 4：Qlib 回测基线

目标：对明确规则做日频/低频、可复现的回测。

实施项：

1. 选一个单市场、单资产类别的起点：建议 A 股宽基/行业 ETF，或美股大盘 ETF。
2. 准备固定历史数据快照，补齐交易日、停牌、成分股变化、复权、费用和滑点假设。
3. 先实现朴素基准：买入持有、固定周期再平衡、简单趋势规则。
4. 再将数据接入 Qlib，运行规则/因子基线与样本外、滚动验证。
5. 固定报告指标：年化收益、波动率、最大回撤、夏普、换手、交易成本、相对基准表现。

验收：每次回测可由配置、数据版本和代码提交复现；策略与基准、成本假设同时展示。

### 阶段 5：盘中提醒（仅研究辅助）

目标：在可信行情下提供实时/近实时事件提醒，不自动交易。

前置条件：确认供应商对目标市场、品种、延迟、频率、授权范围和 WebSocket/事件流的支持。

实施项：

1. 新建独立的行情适配器和进程，不与盘后批处理混用。
2. 校验每条行情的供应商时间戳、延迟、交易时段与断线状态。
3. 实现事件规则：价格阈值、异常成交量、财报发布、宏观数据发布。
4. 建立限频、去重、停市保护、断线告警与人工复核流程。
5. 对 A 股、港股和美股分别验证交易日/时区；延迟数据仅用于观察。

验收：断线、延迟、异常时间戳都会使提醒降级或停止；通知不含自动成交行为。

### 阶段 6：模拟盘与 vn.py

目标：验证策略在订单、延迟和风控约束下的可执行性。

前置条件：阶段 4 有足够样本外结果；阶段 5 有稳定行情；用户明确选择了合规的模拟账户/行情接口。

实施项：

1. 让 Qlib 只输出版本化的“候选信号”；vn.py 独立负责行情、订单、持仓和模拟成交。
2. 配置最大仓位、单标的/行业上限、单日损失上限、交易频率上限和紧急停止开关。
3. 记录订单、成交、拒单、行情延迟、持仓和每日盈亏。
4. 先运行至少一个完整的模拟周期，比较预期回测与实际模拟差异。

验收：模拟盘可审计；风控规则可被主动测试；没有真实券商密钥或真实下单路径。

## 6. 定时与部署策略

- 初期：手动执行 `daily-review`，确认结果正确。
- 盘后：使用 macOS `launchd` 模板执行每日任务；模板默认不启用。
- 长期任务：可迁移到 Docker/服务器或 GitHub Actions，但盘中告警不应依赖一次性 Actions。
- 实时任务：使用单独常驻进程与供应商事件流/WebSocket；需要日志、重连、健康检查和告警。
- 密钥：使用 `.env` 或系统密钥管理，不提交 Git；按数据、通知、交易能力分开授权。

## 7. 建议的下一个开发会话

建议按以下顺序开始，不要一次接入全部项目：

1. 设计并扩展观察列表 schema。
2. 实现一个只读、日频价格数据适配器和本地原始数据缓存。
3. 将每日任务升级为真实的盘后研究报告，包含数据来源与质量检查。
4. 用至少两周的手动运行结果验证数据口径后，再接通知与筛选。

下一会话可直接提出：

> 在 `investment-research` 中执行路线图阶段 1：先设计观察列表 schema 和只读日频价格数据适配器；不接券商、不启用后台服务、不自动下单。

## 8. 决策记录

开始新阶段前，将以下选择记录在 `docs/`：目标市场、数据供应商、数据延迟、复权方式、基准、调仓频率、交易成本、风险限额和验收日期。这样未来的 Agent 或人工复盘都能理解结果的前提。
